## 1. 做了什么

按 `design-system-extract → generate-variations → make-a-prototype` 三步走。

**第一步 · 抽 token。** 从 `DESIGN.md`（raycast）逐字抽出 surface 四级阶梯、三种 hairline、
八个文本色、四个语义色、圆角与间距标度、Inter 及其完整 `font-feature-settings`。§1–§6 与
§9 的 Inter 栈没有一个值是我编的。然后追加项目层：身份色三只、额度阈值、为 960×540 重新
切的九级字号、动效时长与缓动、屏幕几何。文件末尾写了 findings——抽了什么、DESIGN.md 缺
什么、我替项目补了什么、发现的三处内部矛盾。

**第二步 · 定变体的轴。** 简报已经把三个轴定死了（Ledger / Gauge / Strip），我要做的是
把每个轴推到它自己的极端，并保证任意两个之间的差别能一句话说清。三条 caption 见 §3。

**第三步 · 做原型。** 单文件 `variations.html`，中央一块 960×540、1:1 不缩放的 stage，
上方一条工具样式的控制栏（刻意用 system-ui，跟项目字体拉开，提示它不参与设计）。
三个变体共用一份内联的 `tokens.css`，差异只在变体自身的 CSS 与结构；变体走 `data-variant`、
状态走 `data-state`，原生 JS，无框架。fixtures 内联在 `<script type="application/json">`，
不 fetch。`localStorage` 记住变体、状态与 reduced-motion。

`tokens.css` 与 HTML 里的内联副本不是手抄的，是构建步骤拼进去的，已断言逐字相同。

## 2. 字体：选 IBM Plex Mono，不选 JetBrains Mono

简报给的提示是「48px 以上的数字不能读起来像代码」，这条直接决定了结果。

JetBrains Mono 的 x-height 被刻意抬到接近 cap height，字怀开得很大——这是为 12–14px 的
代码行做的优化，目的是在小字号上把 `l/1/I`、`0/O` 撑开。同一套骨架放到 48px，抬高的
x-height 会让数字显得矮而胖，加上它标志性的点心零和高对比末端，读起来就是「终端输出」。

IBM Plex Mono 的数字继承 Plex Sans 的人文主义骨架，x-height 比例更常规，末端更平静，
48px 上是「被排版的数字」而不是「代码里的数字」；它和 Inter 的宽度比例也更接近，
`Claude Code 18%` 这种 Inter 标签 + Plex 数字的混排不会在基线上打架。

两者都在 Google Fonts 上，都带 `tnum`；`zero` 特性我一并打开了，因为副屏上会出现
`8/1000` 这种含零的计数。标签沿用 Inter + `ss03`，这是 DESIGN.md 的签名细节，没动。

代价我认：Plex Mono 在 12px 上不如 JetBrains 清楚。所以 12px 的那一层（轴标签、
事件时间）我控制在两三个字符的短串，不让它承载需要逐字符分辨的内容。

## 3. 三个变体

| | 差异轴 | 一句话 |
|---|---|---|
| **V1 Ledger** | 数字优先，等高行 | raycast 原样：百分比是主角，两条细 bar 做趋势，事件是等高行。信息密度最高、认知成本最低，也最没有记忆点。 |
| **V2 Gauge** | 形状优先，节奏分层 | 5h 窗换成 270°（开口朝下）弧形仪表，倒计时落在仪表中心，身份色只上进度弧；最新一条事件放大成 22px 双行卡，其余压到 40px。读「还剩多少」从读数字变成读形状。 |
| **V3 Strip** | 时间优先，同轴对照 | 主轴从「用了多少」换成「时间走到哪」：每个 agent 一条横向 5h 时间带，额度填充与「现在」游标画在同一根轴上；事件流改成共用时间刻度的竖向时间轴。 |

任意两个之间的一句话差别：
V1→V2 是「同一份信息，从读数字改成读形状」；
V2→V3 是「从读还剩多少，改成读够不够撑到重置」。

### 推荐 V3

理由只有一条，但是硬的：**V1 和 V2 都只回答「还剩多少」，而这块屏真正该回答的是
「够不够撑到重置」。** V3 把这个判断直接画了出来——时间带上有两个标记，额度填充的右端
和「现在」游标，两者的落差就是燃烧速度。填充落在游标后面＝用不完，跑到游标前面＝会提前
用尽。这是另外两个变体给不出的信息，用户只能自己心算「22% 用掉了，可 5 小时窗已经过了
一半」。

edge 态是最好的证据：Codex 97% 看着吓人，但窗口已经走到 99%，V3 直接写「消耗落后时钟
2 个点 · 按这个速度用不完」；Claude 只有 82%，窗口才走到 51%，V3 写「消耗跑在时钟前面
31 个点 · 按这个速度会提前用尽」并转黄。同一屏上，看起来更危险的那个其实没事，看起来
安全的那个才要减速——V1 和 V2 表达不了这个反转。

附带好处：V3 的时间轴一屏多放得下一条事件（1 放大 + 4 行，V1/V2 是 1 + 3）。

风险：5h 时间带在 7 寸屏上只有 20px 高，实机上可能偏细；如果实测读不出来，退而求其次
选 V2——它的仪表弧在远距离上是最强的预注意信号。

## 4. 简报没写、我自己定的决定

1. **时间原点冻结在 fixtures 的 `generatedAt`（2026-09-14 14:33:21 +08:00），之后按真实
   经过秒数递增。** 否则倒计时会和 `quota.json` 里的 `resetsAt` 对不上，截图也不可复现。
   时钟仍然逐秒在走，能看到 tabular 数字换位时不抖。
2. **accent 会随年龄衰减。** 只有最上面那条「未读 / 需要你」拿全套强调（surface 升一档 +
   标题转 ink 加粗 + 6px ink 圆点）；第二条及更老的未读降级成 `--accent-dim` 的圆点。
   否则连点四次「模拟新事件」就有四处 accent，纪律就成了摆设。
3. **事件流的未读计数从 ink 降到 body。** 它本来会白白吃掉第二个 accent 名额，而未读行
   自己已经在说同一件事。
4. **V3 的 attention：顶部 strip 接管之后，事件流不再重复这一条。** 不然同一件事会占掉
   strip、瓦片标记、事件行三个名额。现在稳定是 2 个：strip + 对应 agent 的瓦片标记。
5. **`--ash` 收得比简报更紧。** 简报允许 ≥18px 用 ash，但 ash 在 `--surface` 上实测
   3.64:1，未达 4.5:1 正文线（WCAG 的「大字」是 18pt≈24px，不是 18px）。所以所有有意义的
   小字一律用 `--mute`（7.09:1），ash 只留给非信息性的刻度标记。
6. **focus 用 2px `--ink` 内描边，不用 `--hairline-strong`。** 简报给了两个选项，但
   hairline-strong 叠在 `--surface` 上实测 1.56:1，达不到 WCAG 1.4.11 对 focus 指示器的
   3:1 要求。ink 是 17.05:1。这是纠正，不是偏好。
7. **cwd 从头部收，保留末尾 2–3 段。** 一开始用 `direction:rtl` 做反向截断，结果把
   `~` 甩到行尾（显示成 `…ojects/dsh-ime-demos/~`），读起来是坏的。改成按半角宽度计算
   （CJK 记 2）从头收，现在是 `…/Projects/dsh-ime-demos`。
8. **放大行没有 summary 时，副行让给 cwd，右侧 cwd 列同时留空**，不在同一行里把同一段
   路径印两遍。
9. **V3 的百分比是 18px，不是 48px。** 简报的屏幕规则写了主数字 ≥48px，但 V3 的变体轴
   明确要求「额度百分比退为次级」——两条已定项在这里冲突，我按更具体的那条执行，并把
   数字从最初的 16px 提到 18px，保证手臂距离仍然读得清。V1 / V2 的主数字都是 48px。
10. **每个变体按可用高度定了行数预算**（V1/V2 = 1 放大 + 3 行，V3 = 1 放大 + 4 行），
    超出的条数写在事件流表头（「8 未读 · 另 4 条更早」），不做滚动——副屏上没有滚动的
    交互前提。
11. **loading 用静态骨架，没有 shimmer。** 动效只服务状态变化，循环的微光是装饰。
    骨架旁挂一个 `role="status"` 的「读取中」。
12. **提示音：G5 (784Hz) + D6 (1174.7Hz) 两个正弦，纯五度，180ms 指数衰减，峰值增益
    0.055。** 五度比三度更不像「通知音效」，更像一次轻敲。
13. **running 在事件流里占一条置顶的「进行中」行**，计时逐秒递增；瓦片那边是徽记旁的
    2s 脉冲。两处都有，是因为「谁在跑」既是 agent 的状态也是时序里的一件事。
14. **edge 态里有两处是合成的**，本机数据里不存在：Codex 97% / 3 分钟后重置（阈值演示），
    以及「一分钟内 8 条」的时间戳（真实记录跨了好几天）。两处都基于真实记录改写，标题、
    cwd、agent 归属没动，代码里有注释标明。其余所有事件与额度都直接来自 fixtures。

## 5. 怎么验的

Playwright + Chromium，视口 1100×820，`deviceScaleFactor: 2`，逐个走完 **3 变体 × 7 状态
= 21 个组合**，每个组合跑四类断言：

- stage 内所有后代元素的 bounding box 必须落在 960×540 之内（越界即 FAIL）
- `.feedlist / .tiles / .screen / .tile / .tile-foot / .b-head / .b-axis / .row`
  的 `scrollHeight/scrollWidth` 不得超过 `clientHeight/clientWidth`
- stage 内不存在计算字号 < 12px 的文本节点
- 数一遍全强度 accent（`rgb(244,244,246)` 的未读点 + attention 瓦片 + 可见的 strip）

**最终结果：21/21 通过，0 console error，0 布局问题。** accent 实测分布：
populated / edge / running 各 1 处，attention 2 处，loading / empty / error 各 0 处。

交互也是实跑的：
- 「模拟新事件」→ 行数受预算封顶（4→4），表头从「1 未读 · 另 2 条更早」变成
  「2 未读 · 另 3 条更早」
- Tab 两下进入 stage 第一行，`box-shadow` 实测 `rgb(244,244,246) 0 0 0 2px inset`
- Enter 触发 ack，表头回到「1 未读」，`aria-live` 播报「已标记已读，还剩 1 条未读」，
  焦点留在原行
- 切到 V3 / edge 后 reload，`data-variant=v3 data-state=edge` 正确恢复
- 勾选 reduced-motion 后 `.iddot` 的 `animationName` 实测为 `none`

另外断言过：内联 tokens 与 `design/tokens.css` 逐字相同、两份 fixtures 逐字内联、
无 `fetch()`、无本地 css `<link>`、无 emoji、无 `linear/radial/conic-gradient`、
无 Tailwind 靛蓝系、无裸 `#000000` / `#ffffff`。

## 6. 没能验证的

1. **实机。** 所有判断都是在 Mac 的 Chromium 上按 960×540 逻辑像素做的。7 寸面板、手臂
   距离、@2x 的真实观感没试过。最可能翻车的三项：V3 时间带 20px 高会不会太细、
   12px 那一层在实机上是不是真的能读、48px 数字会不会反而过大。
2. **提示音。** Playwright 是 `--mute-audio` 跑的，只验证了 Web Audio 路径不抛异常，
   **没有真的听过**。音色、响度、在副屏喇叭上会不会太尖，都要实机再调。
3. **V2 仪表的轨道对比度。** 简报定了「轨道用 hairline」，我照做了。但 `--hairline`
   `#242728` 叠在 `--surface` 上实测 **1.29:1**，远低于 WCAG 对非文本图形的 3:1。
   实际效果是轨道几乎看不见，弧的「总长度」要靠猜。现在能读，是因为中心有倒计时、
   右边有 48px 数字兜底。**这条建议在 M1 实机上复核，必要时把轨道提到 `--stone`
   （1.97:1）或更高。** 我没有擅自改已定项。
4. **字体加载失败的样子。** Inter 与 IBM Plex Mono 都从 Google Fonts 拉。Electron 渲染层
   如果离线，会落到 fallback 栈（`system-ui` / `ui-monospace`），字宽和 x-height 都会变，
   48px 数字的负字距可能需要另调。没有模拟过离线渲染。
5. **屏幕阅读器。** `aria-live` 的播报文案写了，`role="status"` 的容器也先于内容存在，
   但没用 VoiceOver 实际听过播报顺序。副屏监视器大概率不是读屏用户的场景，优先级不高，
   但没验就是没验。
6. **系统级 `prefers-reduced-motion`。** 验的是 CSS 媒体查询规则本身 + 控制栏开关；
   没有真的去 macOS 系统设置里打开「减弱动态效果」再看一遍。
7. **长时间运行。** 逐秒的增量更新只改文本和 `left`，不重建 DOM（所以脉冲和呼吸不会被
   打断），但没有跑够长的时间去看 24h 后有没有累积误差或泄漏——那是 M4 的验收项。
8. **真实的 attention 数据。** 「等待你批准」这一档在 PLAN.md 里排在 M4，本机现在没有
   任何真实样本。那条 attention 事件的文案是我照 Claude Code 的 `permission_prompt`
   语义写的，实际字段拿到之后要回头核一遍措辞长度。

原样带进了 3.5 寸版（见下一节），没有任何一条被回退。

## 阻断

**B1 · 轨道类图形一律 ≥3:1**
`--quota-track` 从 `--stone`（1.97:1）提到 `--ash`（3.64:1），并新增 `--quota-fill: --ink`。
落到四处：V1 的 bar 轨、V2 的仪表弧轨、V3 的时间带轨、V3 时间轴的已读节点。
这条改动有两个必要的连带修正，不做的话「提到 ash」反而会让信息更难读：
- 轨道变亮后，原来 `--body` 的填充与轨道只剩 3.28:1，边界发虚 → 填充统一提到 `--ink`，
  填充与轨道之间恢复到 4.86:1。
- V3 的刻度（原 `--stone`）会消失在 ash 轨道里，游标（原 `--ink`）会消失在 ink 填充里
  → 两者统一翻成 `--canvas` 的暗色，无论落在轨道上还是落在填充里都是一道高对比缺口。
- V2 的进度弧是身份色，橙 / 蓝叠在 ash 上按亮度只有约 1.7:1 → 进度弧比轨道宽 2px
  （3.5 寸版是 1px），用形状差补色差，不靠颜色单独传信息。
**验证**：Playwright 逐组合实测 V1 bar 3.64:1 / V2 arc 3.64:1 / V3 band 3.64:1 /
V3 node 3.75:1（已读）·17.69:1（未读），全部 PASS，已固化为断言。

**B2 · loading 的 `role="status"`**
四处「读取中」（三块瓦片 + 事件流）都加上 `role="status"`，并在进入 loading 态时向
`#live` 推一条「正在读取三个 agent 的额度与事件」。原先文件顶部注释和笔记都声称有，
实际没有——这是声明与实现不符，比缺功能更糟。
**验证**：loading 态 `[role="status"]` 计数 = 5（3 瓦片 + 1 事件流 + 1 #live），已固化为断言。

**B3 · stage 内的语义标题**
`.brand` → `h1`，三块瓦片名 → `h2`，事件流标题 → `h2`。用
`.stage :where(h1,h2){margin:0;font:inherit;…}` 重置，`:where()` 不贡献特异性，
所以原有类规则仍然决定全部视觉，**外观零变化**。
**验证**：21 个组合 heading 数均为 5，已固化为断言（≥5）。

**B4 · 事件行 aria-label 拼入 kind**
新增 `KIND_LABEL = {running:"运行中", failed:"失败", attention:"等待批准", completed:"已完成"}`，
同时把相对时间也拼了进去。kind 在视觉上由 `.rkind` 图标传达，而图标是 `aria-hidden`，
不拼进 label 读屏用户就分不清这条跑没跑完。
**验证**：running 行实测 `Codex · 运行中 · 构造 v0.3 盲判任务分类样本 · 4m23s`。

## 质量

**Q1 · `--id-codex` → `var(--charcoal)`（#d3d3d4）**
按 lead 的简报修订 1 执行。这一条同时解掉 R1-01 / R1-03 / R2-11 三个发现，
也给 `--charcoal` 这个「抽了没用」的 token（R1-08）找到了职责。
**验证**：新增断言「非 attention 瓦片上不存在 `rgb(244,244,246)` 的身份点」，21 组合通过；
accent 计数 populated / edge / running 各 1、attention 2、loading / empty / error 各 0。

**Q2 · attention 态下时钟不消失**
960 版：V3 的 topbar 从 `display:none` 改成 sr-only（`h1` 留在无障碍树里），
可见时钟由 strip 右端接管，topbar 那份标 `aria-hidden` 避免读屏听两遍。
**验证**：新增断言「任何变体任何状态下至少一个可见且非空的 `[data-clock]`」，21 组合通过。

**Q3 · V1 / V2 的阈值判语 + 警示图标**
`ok` 级保持沉默（不加填充文案）；`warn` / `danger` 时 `tile-foot` 的时钟图标换成 alert，
文案变成「2h26m · 余量偏紧」/「2m · 余量吃紧」。V2 把它做成 foot 里的独立 chip。
这补上了 R2-05 指出的缺口：V1/V2 的阈值原先只有颜色一个信号。
**验证**：v1 edge foot 实测「2m · 余量吃紧」；v2 三块瓦片实测
`["danger:2m · 余量吃紧","warn:2h26m · 余量偏紧","ok:"]`。

**Q4 · `.row:active`**
`background: --surface-card` + `inset 0 0 0 1px --ash`，`transition-duration: --dur-instant`(120ms)。
规则排在 `:focus-visible` 之前，键盘描边优先级更高。

**Q5 · V3 attention 的事件流表头**
strip 接管后表头原本会显示「全部已读」——单独看下半屏会以为没事要处理。
改成「1 项在上方等待」。

**Q6 · `.attn-tag` 字距** `--tr-caps`(.08em) → `--tr-small`(.01em)。它渲染的是中文「等待你」，
ALL CAPS 的 tracking 规则对 CJK 不适用。

**Q7 · attention 行边框** `--hairline-strong`(1.54:1) → `--ash`(3.64:1)。

## 打磨

**P1 · 间距回栅格** 29 处 gap / padding 收到 2/4/8/12/16/24/32。剩 5 处例外全部是字形几何
而非节奏（V3 `.tile` gap 2px、`--dot` 6px、徽记前导点 5px、游标 3px、时间轴节点 11/3px），
已在 `tokens.css` §6 逐条列名并说明理由。

**P2 · 跨阈值播报** 额度从 ok 跨到 warn / danger 时向 `#live` 推一句，只在跨越那一刻播一次，
不是逐秒念。**验证**：populated → edge 实测「Claude Code 5h 额度已达 82%，余量偏紧」。

**P3 · breathe 去掉 `filter:brightness`** 改成一层 `pointer-events:none` 的 ink 叠层动 opacity，
纯 GPU 合成，不再触发 paint。峰值 6% 不透明度把 `#101111` 在 sRGB 数值上抬约 14/255 ≈ 5.4%，
仍在简报的「亮度不超过 8%」之内。这里对「8%」采用 sRGB 数值口径而非线性亮度口径——
线性口径下 8% 在近黑面上肉眼完全不可见，那样的呼吸等于没有。

**P4 · V3 的 18px 主数字** 按 lead 的简报修订 3 予以接受，不改。3.5 寸版沿用同一取舍，
数字是 16px。

## 断言变更

新增四条，全部固化进 `verify.mjs`，21 个组合逐个跑：
轨道 ≥3:1 · attention accent ≤2 · stage 内 heading ≥5 · loading 存在 `role="status"`。

现在只对结构容器判纵向裁切，横向逃逸交给 stage 边界那条，另加一条
「凡靠省略号收尾的元素必须真的 `overflow:hidden`」。

# 3.5 寸版

用户实机确认副屏是 **3.5 英寸**（不是 7 寸），1920×1080 物理 / 960×540 逻辑，
并在 1x / 1.5x / 2x 三档字号比对里选了 **2x**。按 `design/brief-m0-35.md` 重做。

## 为什么不是把 960 的版面缩小

960 那版是按 7 寸推的，字号下限也是按 7 寸定的。屏幕砍一半、字号不动，等于把所有
文本的物理尺寸砍一半——那正是用户觉得字小的原因。所以这一版是**重排**不是缩放：
画布改成 480×270 CSS px，整个 stage 挂 `zoom: 2` 铺满 960×540。
1 画布 px = 4×4 物理像素 = 0.16 mm（1920×1080 @ 3.5" ≈ 629 ppi），
比普通桌面显示器的 1 px（约 0.26 mm）还小 0.6 倍——换句话说，画布坐标里的 12px
在这块屏上看起来只有普通屏上 12px 的六成大。所以内容必须砍。

## 砍了什么

| 砍掉的 | 理由 |
|---|---|
| 品牌字「AGENT MONITOR」 | 它不回答那两个问题里的任何一个，纯占 28px |
| 事件流的卡片外壳与表头 | 省下 18px 的 padding + 30px 的表头，全给事件行本身 |
| 未读计数、「另 N 条更早」 | 屏上只剩 1–2 条事件，计数是在数看得见的东西 |
| 事件行的 cwd | 「在哪个项目」不是马上要行动的信息；它也是唯一一条因此不再适用的 edge 边界 |
| ZCode 空态的「怎么接」那句 | 按简报移到托盘菜单，屏上只留「未连接」+ 一行原因 |
| error 的两段式文案 | 原因与下一步压成一句 |
| V2 的 7d 窗、V1 的 7d 独立 bar | 7d 在 5h 窗面前永远是次要的 |
| ZCode 的 1mo（MCP 8/1000）窗口 | 三个窗口里最不紧急的一个，本画布放不下 |
| 事件流第 3–5 行 | 预算只够 1 条放大 + 1 条次新（V3 只够 1 条） |

留下的：三个 agent 名 + 状态点 + 5h 百分比（V1 48px / V2 44px / V3 16px）+ 重置倒计时
+ 一条放大的最新事件 + 右上角时钟。

## 三个变体

| | 砍法 | 一句话 |
|---|---|---|
| **V1 Ledger** | 7d 退成 12px 次级数字，只留一条 3px 细 bar | 48px 百分比一字排开，认得最快，也最没有形状记忆点 |
| **V2 Gauge** | 7d 整个不显示；60px 弧内只放倒计时，44px 百分比放弧旁 | 砍得最狠，但远处先看到弧的缺口，走近才读数字 |
| **V3 Strip** | 事件区只留一行；百分比退成 16px | 三条竖向时间带，填充与「现在」游标同轴，判语压到 12px 保留 |

两两差别：V1→V2 是「从读数字到读形状」；V2→V3 是「从读还剩多少到读够不够撑到重置」。

## 推荐：V1（相对 7 寸版的改判）

7 寸版我推荐的是 V3，理由是只有它把「够不够撑到重置」画了出来。3.5 寸上这个理由不成立了：
时间带只剩 **10px 高**，在 50–60 cm 外基本读不出填充右端与游标之间那点落差，
V3 最值钱的机制退化成一句 12px 的文字——而那句话 V1 的 `tile-foot` 也放得下
（返工 Q3 已经加了「2m · 余量吃紧」）。

在这个尺寸上，**48px 的数字是唯一能从座位上一眼读到的东西**，V1 把整块预算押在它上面，
这是最诚实的分配。V2 是第二选择：弧的缺口在余光里比数字更容易被注意到，
代价是 7d 完全看不见。V3 留作参考——如果之后换回大屏，它仍然是信息量最高的那个。

## 这一版新做的判断（简报没写的）

1. **瓦片头只留名字 + 身份点，状态词下沉到 `tile-foot`。** 149px 宽的头里塞不下
   「Claude Code」+「等待你」+ 点，实测名字被省略号吃成「Claude Co…」。
   现在 foot 按优先级显示：等待你批准 > 额度判语 > 运行中 · 倒计时 > 倒计时后重置。
   这样每个状态都仍有文字信号，不靠颜色单独传。
2. **百分号拆成 14px 的独立后缀。** 「22」用 48px、「%」用 14px 基线对齐。
   这不只是排版趣味——`56px 弧 + 44px「22%」` 在 127px 的瓦片内宽里放不下，
   拆开之后 `60 + 4 + 52.8 + 8.4 = 125.2` 刚好进得去，主数字才保住了 44px 底线。
3. **V2 在 ok + idle 时 `tile-foot:empty` 整条收掉**，仪表回到瓦片真正的垂直中心；
   有判语或状态词时它才出现。符合简报「ok 级保持沉默」。
4. **attention 不再另起全宽 strip**（960 版是 V3 专属的 strip）。3.5 寸上一条 44px 的
   strip 会吃掉半个事件区；改成最新事件行自己变成 attention 行，标题前缀「等待你」。
   accent 仍然是 2 处：attention 行 + 对应 agent 的瓦片标记。
5. **h1 与事件区标题转为 sr-only。** 品牌字按简报砍掉了，但文档大纲不能跟着塌，
   所以保留一个不可见的 h1 和一个不可见的 h2，heading 数仍是 5。
6. **V3 的百分比是 16px。** 沿用 lead 已接受的取舍（V3 的轴定义「额度退为次级」
   比通用的主数字底线更具体）。

| **attention** | **谁在等我。** 整屏专用页接管，轮播暂停直到解除。28px「等待你」+ 18px 说明 + 已等多久。 |

## 节奏取值的理由

- **A 10s / B 6s / C 6s（一轮 22s）。** 轮播最大的坑是「扫一眼时想看的不在屏上」。
  A 是回归页，让它占掉将近一半的周期，随机一瞥命中它的概率才够高（10/22 ≈ 45%）。
  B 与 C 的 6s 是「一行放大标题 + 两三行次级」读完所需，再短会读不完。
- **空闲加速 B/C 各 4s**：30 分钟无事件且无 agent 在跑时，屏上没有新信息，
  缩短非总览页等于把回归周期从 22s 压到 18s。4s 是简报的硬下限，不再往下压。
- **新事件钉住 20s**：比 C 的常规停留长三倍多，因为这时 C 页上有一条你还没看过的东西；
  期间再来一条会重置这 20s（否则连续到达会让第一条只露 2s）。
- **attention 不计时**：它不是一页而是一个状态，只有解除才走。

# 实机反馈 1

用户把轮播版放到副屏上看了，两条反馈，已写进 `brief-m0-rotation.md`。

## 节奏：10/6/6 s → 每页 60 s

**原来的设计假设被实机否掉了。** 我当初给 A 页 10s、B/C 各 6s，理由写在笔记里：
「轮播最大的坑是扫一眼时想看的不在屏上，所以让总览页占掉将近一半的周期，
随机一瞥命中它的概率才够高」。这个推理的前提是**人会盯着屏等**——实机上不是。
副屏是余光扫的，页太快的结果是每一眼都撞在切换动画上，而不是撞在内容上。

改成 60s 之后，回归靠的不再是**频率**而是**打断**：新事件与 attention 会主动把该看的
推到眼前，定时轮播退成兜底。「空闲加速」也随之作废——既然不靠频率回归，
空闲时缩短停留就失去了意义，规则和 `--dwell-idle` 一起删掉了。
新事件跳 C 后改为停满一个 dwell（60s），再来一条重新计时。

断言相应加了一条硬的：**三页 dwell 的默认值必须都是 60000ms**，
且 `--dwell-idle` 不得再存在。页序测试仍然把 dwell 临时压短来跑——那只是为了在几秒内
观察机制，token 的默认值不跟着改。

## 纯净模式

标签栏、地址栏和原型自带的控制栏都会破坏副屏观感，所以加了「只有画布」这一档：
`?pure=1` 或任何时候按 `P` 进入，控制栏与说明全部隐藏，`body` 背景直接是 `--canvas`，
画布居中铺满视口，同时请求 Fullscreen。`Esc` 或再按 `P` 退出；用户直接按 Esc 退出
浏览器全屏时，`fullscreenchange` 会把视图同步退回调试态，不会卡在半纯净的状态。

两处是实现层面必须做的判断：

1. **Fullscreen API 必须由用户手势触发**，所以 `?pure=1` 打开时只能先切视觉、
   挂一行 14px 的「按任意键进入全屏」，按键后再请求——提示只出现这一次。
   直接按 `P` 进入时本身就是手势，不需要这一步。
2. **`P` 的守卫范围**。第一版写成「焦点在任何控件上就不响应 P」，结果勾选框和按钮
   拿到焦点后 P 就失灵了——而 harness 里根本没有文本输入。收窄成只给真正会打字的
   地方让路（contenteditable / textarea / 文本类 input）。**这条是断言抓出来的**，
   不是我自己发现的。

纯净模式下轮播强制开、忽略 `localStorage` 里的手动选页（进入时直接回 A 页）；
键盘 ack 与右下角指示点保留。控制栏里也加了「纯净全屏」按钮做同一件事。

## 验收

全部断言重跑：**28 格 × 10 项全过**（画布边界 / 裁切 / 字号 ≥14 / heading ≥5 /
role=status / 时钟 / accent ≤2 / 轨道对比度 / 间距栅格 / inert），
节奏 6 条全过，**纯净模式 8 条全过**（进入、隐藏控制栏与说明、body 背景 = --canvas、
轮播强制开、指示点保留、Esc 退出、`?pure=1` 的 14px 提示与按键后消失、
纯净模式下 Tab 到事件行且 Enter 能 ack）。0 console error。
截图按要求未重出（版面未变，只有节奏与模式开关变了）。

**仍未验：** 60s 这个新值同样是推算——它解决了「太快」，但会不会变成「太慢以至于
想看 B 页要等一分钟」，只有下一轮实机能回答。纯净模式的 Fullscreen 在 Electron 里
走的是另一套（`setSimpleFullScreen`），本版验的是浏览器行为。

# 手动切换（M0 最后一次改动）

自动轮播之外补了手动翻页。四种触发方式，一个共同的后果（暂停 120 s）。

## 触发

- **键盘** `←` / `→` 上一页 / 下一页，`↑` 或 `Home` 回 A。
- **指示点**点击直接跳页：**热区放大到 24×24，视觉仍是 4px**。做法是把点本身画成
  `button::after`，`button` 只负责命中——这样「看得见的」与「点得到的」可以各自取值，
  不必为了好点而把点画大。
- **边缘热区**：画布左右各 15% 宽，无常驻控件；鼠标移入才浮出一个 24px 的 monoline
  chevron，2 s 无移动即隐藏。副屏上常驻箭头是纯粹的视觉噪音，它一年里有 364 天不需要。
- Electron 版的全局快捷键 `⌃⌥←/→/↑` 属 M1，本版未做。

## 手动之后

手动切页后轮播暂停 `--manual-hold`（120 s），指示点左侧挂一个 14px 的「‖」。
这个标记不是装饰：没有它，用户按停之后再看到屏不动，第一反应会是「轮播坏了」。
120 s 到期后从**当前页**继续，不跳回 A——人停在哪一页就是他想看那一页。

**打断优先级不变**：手动暂停期间来了新事件仍跳 C 并重新计时（`holdUntil` 被清零），
attention 仍接管整屏。attention 页**不能**被手动切走——它需要被处理——但可以按 Enter
ack 解除，解除后回 A 并恢复轮播。纯净模式下以上全部可用。

## 两个由断言抓出来的 bug

1. **方向键守卫过宽。** 第一版写成「焦点在控制栏里就不响应方向键」，结果用户点完
   控制栏按钮之后焦点留在那儿，**第一次按 `→` 永远失效**。`<button>` 对方向键没有
   原生语义，收窄成只给真正会用方向键的控件（文本 input / textarea / select /
   contenteditable）让路。这与上一轮 `P` 键守卫是同一个错误，我犯了两次。
2. **「‖」不会自己消失。** 原来只在 `showPage()` 里更新，于是 120 s 到期后只要没有
   翻页动作，标记就一直挂着——正好是它最会误导人的那一刻。改到每 100 ms 的
   `updateMeter()` 里刷新。

还有两处是**断言自己的口径错**，一并记下来，因为它们都属于「测试比实现更容易骗人」：
测 Enter ack 时单按一次 Tab 只落到隔壁的控制栏按钮上（改成一路 Tab 到焦点真的进画布）；
判断 attention 是否解除时找的是「还有没有 attention 行」，但那一行 ack 之后本来就该

## 三个要解释的决定

**热力图配色：中性明度阶，不是绿也不是蓝。** 0 档用 `--surface-elevated`，1–4 档沿
`--charcoal` 方向的中性阶，顶档就是 `--charcoal` —— 也就是 `--quota-fill` 的颜色。
不用 GitHub 的绿是简报的要求；**不用 `--accent-blue` 是我的判断**：ZCode 的身份色
`#6f93e6` 就是蓝，一屏蓝格子加一个蓝图例点会让人以为格子按 agent 分了色，
而简报明确要求格子只按总量分档。用中性阶还有一层好处：它在这套系统里已经有稳定含义
（「这是数据，不是强调」），顶档不会被误读成 accent。

**模型名用 sans 不用 mono。** 模型名是专名不是数字，`Fable 5.1`、`gpt-6-astra` 混合
大小写与连字符，Inter 的字形区分比等宽好；mono 会把字母也拉成等宽，读起来像代码路径。
数字仍然一律 mono——这条分界线全项目一致：**数字用 Plex Mono，名字用 Inter**。
ZCode 的 `GLM-5.3-Flash` 是 `events.json` 里 `source` 字段的真实值；Codex 与 Claude
的会话记录里没有模型名字段，先用简报给的例子占位，M1 接真实数据时替换。

**tooltip 报三家各自的单位，不报一个「统一的请求次数」。** 简报希望统一成请求次数，
但 `usage.json` 的实际来源是 `codexbar cost` 的 **token 数**（Codex / Claude）与 ZCode
日志里的**请求条数**——三家拿不到同一个量。fixture 自己的 note 也写了「units differ
per agent」。所以分档用 `intensity`（每家各自归一化后取均值，0–1），tooltip 则如实写
`Codex 0 tok · Claude 2.3亿 tok · ZCode 233 次`。**编一个统一数字比不统一更糟**，
它会让人拿三家的数去比大小。

## REVISION 10 · 100% 放不下 + 模型名并进产品名（用户 2026-09-15 实机反馈）

用户在实机上把额度跑到 100%，发现横向放不下。根因不是「没算」，是**算在了错的画布上**：
R5-11 当时写「实测 64px 三位数约 111px < 133px 内宽，放得下」——133px 是 480 画布的瓦片内宽，
而实机跑的是 panelX 1.19，瓦片内宽只有 105.67px，64px 的「100」要 115.2px。
**一个只在一种画布上成立的结论，被当成了结论。** 这是这轮的第七次同型：
前六次是「该出现的没出现 / 不该出现的出现了 / 出现的不是这一版 / 出现的是错的那一种 /
出现的被切掉了一半 / 引用的东西根本不存在」，这次是**「算过，但只算了一种画布」**。

1. **A 页三位数降一档**：数字 `--fs-num-a-wide` 52px、% `--fs-unit-a-wide` 16px，两位数一个像素不动。
   R5-11 那条「藏掉 %」的修法一并作废——藏掉它只省 12px（不够），代价却是「100」读成裸数字。
   实测 403 画布上「100%」= 93.6 + 2 + 9.6 = 105.2 ≤ 105.67，四种画布全过。
2. **B 页数字列定宽**：`.b-pc` 4ch（20px mono = 48px）、`.b-sec` 7ch、`.b-cd` 5ch，全部 tabular。
   「100%」与「7%」从此占同一格，打满时不再把 7d 与倒计时往外挤；
   附带收获是三行的百分数第一次对齐成一列（原来每行各在各的位置上）。
   `.b-sec` 同时从 16px 降到 14px：5h 是主角（20px），7d 是参考值，两者原来只差 4px 读成同一层。
3. **模型名并进产品名**（用户追加）：`● Codex · Astra`、`● Claude Code · Fable 5.1`、`● ZCode · GLM-5.3`，
   短名 `--mute`、同字号同基线，判语那一列整个取消，宽度还给数字与倒计时。
   fixtures 的模型名改成短名（Astra / Fable 5.1 / GLM-5.3）——短名不是把实测值截断，
   是模型的通用叫法，断言卡 ≤10 字符。
   **三条不显示模型的规则**：没有模型数据时连「·」都不出现；有状态词（等待你批准 / 运行中）时不显示；
   **warn / danger 时也不显示**——实测 403 上「Claude Code · Fable 5.1」+ 警示图标 + 100% + 7d 100%
   + 倒计时放不下，会变成「Claude Co… · Fabl…」**两个都被省略**，而额度吃紧时该读的是额度不是模型。
   产品名本身设了 `flex-shrink:0`：A-2 的教训是把它省略掉就等于把身份降级成一个颜色点。
4. **新增 `full` 场景**（三家同时 100%、7d 也 100%），不替换 `edge`：
   edge 的 97 / 82 / 61 覆盖 danger / warn / ok 三档同屏，full 覆盖最宽的数字，两个场景各管一件事。
   格子检查从 196 涨到 224（4 画布 × 7 页 × 8 态），另出 `page-a-full` / `page-b-full`（含 -x119）四张图。

**新增断言**：
- `A-NUM`：数字与 % 必须同基线，三位数必须已降档（≤52px），两位数必须仍是 64px，% 必须渲染出来。
  量基线用的是「零高度 inline-block 的底边」——baseline 对齐时两个 box 的 bottom 差的是各自
  descender（52 / 16px 差出 7 画布 px），拿 bottom 比会把对齐的报成没对齐，这条第一版就踩了。
- `B-MODEL`：模型短名 ≤10 字符、有「·」必有名字、省略不得超过一半（与 E-1 同一套「允许省略，
  不允许省略到读不出是谁」的口径）。
