### 物理上下文（判可读性时已代入）

3.5 英寸 3:2 面板，系统以 960×540 @2x 驱动，面板缩放器横向压 15.6%，app 用 `panelX = 1.19` 反向拉伸。
**故截图里字形偏宽是正确的，到屏上正好抵消，本报告不把它计为字形缺陷。**
1 画布 px ≈ 0.16 mm，观看距离 50–60 cm。据此：14px ≈ 2.24 mm（团队自己实测的「只能认」档），
64px ≈ 10.2 mm（「座位上能读」）。**横向量度按画布逻辑 px 算**（403 宽），
**器件像素换算**：1 画布 px = 4.76 器件 px（横）/ 4 器件 px（纵）。

### 先记下做对的地方（避免下游「修」掉它）

这一版的底子是干净的，下面几条**不要动**：

- **reduced-motion 是完整的**：`@media (prefers-reduced-motion:reduce)` 与 `html[data-rm="1"]` 双路，
  同时压 `animation` / `transition` / `.page` 的 `transform`（`app.css:385-392`）。切页位移也被关掉了，
  多数实现会漏掉最后这一条。且**没有**把静音绑在 reduced-motion 上（`app.ts:311` 的注释写清了理由）——
  这是对的，运动偏好不是听觉偏好。
- **focus 用 `:focus-visible` 不用 `:focus`，且没有一处裸 `outline:none`**：每处 `outline:none` 都配了
  2px `--ink` 的 `box-shadow` 环（`.row` / `.dots button` / `.edge` / `.cell`），在 `--surface-card` 上 17.05:1，
  远超非文本 3:1 的硬线。
- **语义结构**：单个 `h1.sr` + 每页 `h2.sr`，无跳级；离屏页用 `inert`（不是只靠 `aria-hidden`）；
  `role="status" aria-live="polite"` 在位。
- **时长全部在band内**：`--dur-instant 120ms`（按下）/ `--dur-state 180ms`（状态）/ `--dur-bar 300ms` /
  `--dur-page 300ms` / `--dur-event 360ms`。没有一处超过 400ms 的微交互。
- **ai-slop 清单全清**：`grep -c gradient app.css` = **0**；无 emoji（图标是 1.7px 描边 monoline SVG，
  `currentColor`）；无默认左侧色条卡片；无 `#fff` / `#000`；颜色全部追溯到 token。
  Inter 虽在 slop 清单的「默认字体」栏，但它来自 raycast 真源（`DESIGN.md`）且有书面理由，**不计为 slop**。
- **间距栅格出奇地干净**：画布内只有 3 个离格值（`.b-head` 22px、`.d-days` 26px、JS 的 `cell` 13px）。
  harness 的一堆 11px / 5px 是**刻意**的系统外观，不算。
- **指示点的热区 24×24、视觉 4px** 用 `place-items:end center` 同时成立——这是个漂亮解。

## 1. A 页 · 总览

### A-1 · **P0** · `.tile-foot` 把「后重置」硬切成「后重」，倒计时 ≥1h 时必现 · 置信度 **确定**

**页面 / 选择器**：A 页 · `src/renderer/app.css:181` `.page-a .tile-foot` ＋ `src/renderer/app.ts:705` 的 `'后重置'`

**证据（同一帧内的对照，无需推断）**：`m4/live/page-a.png`，时钟 23:00，三块瓦片并排——

| 瓦片 | 倒计时字符数 | 屏上文字 |
|---|---|---|
| Codex | `4h59m`（5） | 「4h59m **后重**」＋「置」的左半 |
| ZCode | `4h00m`（5） | 「4h00m **后重**」＋「置」的左半 |
| Claude | `59m`（3） | 「59m **后重置**」完整 |

**机制**：`.tile-foot` 写的是 `white-space:nowrap; overflow:hidden`，**缺 `text-overflow:ellipsis`**。
于是溢出不是省略而是 **hard clip**——在字符中间齐口切断，屏上留下的是一个残缺字形，不是一个截断信号。

宽度账（画布逻辑 px）：

```
canvas 403  →  .screen inset 8  →  387
tile        =  (387 − 2×8 gap) / 3           = 123.67
tile 内宽   =  123.67 − 2×8 padding − 2×1 border = 105.67
foot 需宽   =  icon 15 + gap 4 + cd + gap 4 + word
              cd  : IBM Plex Mono advance 0.6em，18px → 10.8 px/char
              word: 「后重置」14px 全角 → 42
  cd = "4h59m"(5)  → 15+4+54.0+4+42 = 119.0   → 溢出 13.3px ≈ 0.95 个全角字
  cd = "59m"  (3)  → 15+4+32.4+4+42 =  97.4   → 放得下
  阈值：cd ≤ 3 字符才放得下
```

**为什么是 P0 而不是 P1**：
① 违反简报的硬线（`brief-m0.md` 自检表：「没有裁切文本（64 字标题用省略号 `…`，不是三个点）」）；
② 5h 窗有 4h 的倒计时是 ≥1h 的 5 字符形态，**约 80% 的时间必现**；
③ 它在 A 页——轮播恢复的默认页、用户抬头最常看到的那一屏；
④ 三块瓦片同时中招，不是个例；
⑤ 「后重」不是「被截短的词」，它是**另一个词**——残缺字形比省略号更糟，因为它不告诉读者有东西被切掉了。

**修法（按「AI 加法，人减法」优先级排）**：

1. **首选：把「后重置」整个删掉。** 左边已经有一个 15px 的 monoline 时钟图标，
   `🕐 4h59m` 在这套系统里语义自足；「后重置」是对图标的**文字复述**，正是简报第 2 条
   （删判语、靠时间带承担）已经确立过的减法。删掉后 foot 需宽 = 15+4+54 = 73 < 105.67，
   余量 32px，三位数百分比与更长倒计时都安全。
2. 若坚持保留语义词：给 `.word` 加 `min-width:0; overflow:hidden; text-overflow:ellipsis`，
   并把词缩成单字「后」（14px，省 28px）。
3. **无论选哪条，同时做 A-1b（见下）**——这是一个类，不是一个实例。

### A-1b · **P1** · 「`overflow:hidden` 无 `text-overflow`」是一个类，画布里有 3 处 · 置信度 **确定**

**位置**：
- `app.css:181` `.page-a .tile-foot` —— 已在 A-1 现形
- `app.css:262-264` `.rtime` —— `width:88px; overflow:hidden`，无 ellipsis。今天 `9/10 14:41` 恰好 84px 放得下；更长的时间串会齐口切数字
- `app.css:218` `.page-b .b-cd` —— `width:48px; text-align:right`，既无 `overflow` 也无 ellipsis。`4h59m` 14px mono = 42px；6 字符（50.4px）会向左压到 7d 的百分数上

**机制**：这三处都把「必须完整出现的定长字段」交给一个**固定宽度的裁切盒**，
而裁切策略只写了一半（裁，不省略）。`.rtime` 的注释甚至写明「加 overflow:hidden 兜底」——
兜底做了，兜底之后的**可读信号**没做。

**为什么断言没抓到**：`design/verify.mjs:91-106` 的 `clipped()` 显式豁免「有裁切祖先的元素」——
这个口径对**内联省略**是对的，对**硬裁切**是错的，两者在 rect 上不可区分。
这是设计师笔记里那串同型教训的**第五面**：
① 该出现的没出现（E 页的时间）② 不该出现的出现了（截图里的合成行）
③ 出现的不是这一版（STAGE 段漂移）④ 出现的是错的那一种（D 页 edge 谎报空态）
⑤ **出现的被切掉了一半，而断言看不见**。

**修法**：
- 三处统一补 `text-overflow:ellipsis`（`.b-cd` 还需补 `overflow:hidden; min-width:0`）；
- 在 `verify.mjs` 里补一条**内容级**断言（与 E 页 `.e-time` 那条同型）：
  对 `.tile-foot` / `.rtime` / `.b-cd` 逐个比对 `scrollWidth > clientWidth`，
  若成立则该元素必须解析出 `text-overflow: ellipsis`，否则红。
  口径落在「裁切策略完整」上，而不是「rect 越不越界」上。

### A-2 · **P1** · 「Claude Co…」——瓦片唯一的身份标签被省略掉了一半 · 置信度 **确定**

**页面 / 选择器**：A 页 · `app.css:121` `.tile-name` ＋ `app.css:171` `.page-a .tile-name{font-size:var(--fs-body-r)}`（16px）

**证据**：`m4/live/page-a.png` 中间瓦片 —— 「**Claude Co…**」。Codex、ZCode 完整。

**机制**：`.tile-head` 是 `justify-content:space-between` 的 flex，`.tile-name` 与 6px `.iddot` 争夺
105.67px 内宽。「Claude Code」11 字符 Inter 16px ≈ 92px，加 dot 6 + gap 4 = 102px——
理论上差 3.7px 就够，实测被 `letter-spacing` 与 `--panel-x` 的横向拉伸吃掉。
这不是 bug，是**没有为压缩补偿留余量的行宽预算**。

**为什么是 P1 而不是打磨**：A 页只回答一个问题（还剩多少），
而「这是谁的额度」是这个答案的**主语**。三块瓦片里有一块的主语读不全，
在 0.16 mm/px、55 cm 距离下，用户要靠身份色点去补——**把一个文本标签降级成了颜色单通道编码**，
这正是 accessibility-audit「color-only signaling」那条要防的。

**修法**：A 页用短名 **`Claude`**（与 D 页图例、C 页 `CLAUDE` 徽记已经在用的短名一致，
反而消除了 A/C/D 三页称谓不统一的问题）；B 页画布更宽，保留全名 `Claude Code`。
在 `AGENTS` 里区分 `name` / `shortName` 两个字段，由页面选取，不在 CSS 里靠 `max-width` 硬压。

### A-3 · **P2** · 64px 数字旁的 20px `%` 读成下标 · 置信度 中

`app.css:178` `.a-nums .unit{font-size:var(--fs-unit-r)}`（20px），与 `--fs-num-a`（64px）
在同一 baseline 上，比例 3.2:1。baseline 对齐在排版上是正确的，但在这个尺寸差下
`%` 落在数字的下三分之一，**读成 superscript/subscript 而不是单位后缀**。
修法：把 `%` 提到 `align-self` 相对 cap-height 中线（`transform:translateY(-0.22em)` 或
改用 `align-items:center` + 手动光学微调），或直接把它压到 `--mute` 让它退出主视觉层。
优先级低——它不妨碍读数。

### A-4 · **P2** · IBM Plex Mono 的带点零，在 64px 上正是简报担心的那个效果 · 置信度 中

`m4/live/page-a.png` Codex 瓦片的 `0` 中心有一颗椭圆点（Plex Mono 的 disambiguated zero）。
简报选 mono 时明写「48px 以上的数字不能读起来像代码」，设计笔记 §2 也是照这条选的 Plex——
但**带点零恰恰是 mono 最像代码的那个字形**，而它只在数字大到能看清点的时候才暴露。
修法：`.num` 上加 `font-feature-settings: ... , "zero" 0`（Plex Mono 的 `zero` 是可关的 feature），
只关 64px 的 A 页主数字，14px 的时钟/时间戳保留带点零（小字里它确实帮助区分 0/O）。
**这是一处判断题，交作者定**：要「大字不像代码」还是「全项目字形一致」。

## 2. B 页 · 额度详情

### B-1 · **P1** · `--ash` 轨道是全屏最亮的一块，而它承载的是「没用掉的部分」——层级反转 · 置信度 **确定**

**页面 / 选择器**：B 页 · `app.css:145` `.bar{background:var(--quota-track)}`（= `--ash #6a6b6c`）
＋ `app.css:219-227` `.page-b .band` / `.used`

**证据**：`m4/live/page-b.png`。三条 12px 高、约 360px 长的带子，98% 以上是中灰实心。
身份色填充分别是 0% / 2% / 1%——Codex 那条**完全看不到填充**，整条读成一块均匀的灰。
在 55 cm 距离上扫一眼，三条带子的信息是「满的」，而真实答案是「几乎没用」。

**机制**：`--ash` 在 `design/tokens.css:36` 的注释里写着
`3.64:1 — NON-INFORMATIONAL MARKS ONLY`。这里它被用作**最大面积的实心填充**，
在 figure/ground 关系上把「容量」（背景信息）推成了 figure，把「已用」（前景信息）压成了 ground。
轨道升到 `--ash` 本身是 R3 为满足 **WCAG 1.4.11 非文本对比度 3:1** 做的正确修复——
但 1.4.11 要求的是 **组件边界可辨识**，不是**组件内部必须实心填成 3:1**。
用实心大色块去满足一条关于边界的规则，代价就是把数据层级翻了过来。

**修法（同时满足 1.4.11 与层级）**：
把轨道从「实心 ash 板」换成「暗底 + ash 描边」：

```css
.bar, .page-b .band {
  background: var(--surface-elevated);       /* #101111，退回 ground */
  box-shadow: inset 0 0 0 1px var(--ash);    /* 边界仍 3.64:1，1.4.11 照过 */
}
```

填充仍是身份色（`--quota-fill-codex/-claude/-zcode`），末端 2px `--canvas` 缺口保留。
这样 **屏上最亮的东西变回「已用掉的量」**，Codex 的 0% 会正确地读成「一条空轨道」而不是「一条满带子」。
REVISION 7 的结论（边界靠缺口不靠色差，填充对缺口 6.42–13.39:1）不受影响——缺口机制与轨道亮度无关。

### B-2 · **P1** · 「现在」游标与填充末端缺口用了**完全相同**的 2px `--canvas` 缺口 · 置信度 **确定**

**页面 / 选择器**：`app.css:229` `.band .caret{width:2px; background:var(--quota-notch)}`
vs `app.css:146-148` `.bar>i{box-shadow:var(--quota-notch-w) 0 0 var(--quota-notch)}`
（`--quota-notch` = `--canvas`，`tokens.css:142`）

**证据**：`m4/live/page-b.png` Claude 那条从左到右是——
`橙色填充 | 2px 黑缝 | 灰 | 2px 黑缝 | 灰 | 亮白竖标`。
两道黑缝**像素级相同**，但第一道意思是「已用到此为止」，第二道意思是「现在几点」。
（已核对数值：Claude 1h37m 后重置 → 窗口过去 67.7%，游标实测落在 67.7% 处，逻辑是对的。）

**机制**：同一个视觉词汇（2px canvas gap）被指派了两种语义。
缺口是**分隔符**（figure/ground 边界），游标是**基准标记**（datum）——
两者在信息类型上完全不同，却没有任何 affordance 差异。
对照之下，重置刻度 `.resettick`（`app.css:236`）用 `top:-2px; bottom:-2px` 的**出头** + 高亮度
把自己区分开了——**同一条带子上已经有一套正确做法，游标没有沿用它**。

**修法**：让游标沿用 resettick 已经确立的词汇，但取反向以保持三者可分：

```css
.page-b .band .caret{
  top:-3px; bottom:-3px;          /* 出头，和 resettick 同族 */
  width:2px; background:var(--ink);  /* 实心亮线，而不是挖空 */
}
```

结果：**挖空 = 数据边界**，**出头亮线 = 位置基准**（游标 `--ink` 细高、重置 `--ink` 短粗且贴右端）。
三种标记三种形，不靠颜色，在 2.2 mm 的带高上也分得开。

### B-3 · **P1** · 模型名被截成 `GLM-5.3-F…`，且 5h 百分比是整行唯一没有标签的数字 · 置信度 **确定**

**证据**：`m4/live/page-b.png` ZCode 行 —— 「`GLM-5.3-F…`」。
同一行从左到右六个字段：`● ZCode | GLM-5.3-F… | 1% | 7d | 20% | 3h59m`。
**只有 `7d` 带标签，`1%`（5h）不带**——读者看到两个百分数，一个有 `7d` 前缀，一个没有，
必须推断「没标签的那个就是 5h」。这是把标注责任推给读者。

**机制**：`.b-head` 是单行 flex，六个字段线性排列，靠 `flex:none` / `flex:1` 分配。
模型名（`.b-verdict`，`app.css:208`）拿 `flex:1`，是唯一会被压缩的那个——
于是**最长的可变字段总是被牺牲**（与 E-1 是同一个模式）。

**修法**：
1. 给 5h 百分比补一个 `5h` 标签，与 `7d` 对称（成本：14px × 2 字符 ≈ 17px，从模型名借）。
   或者反过来——把 `7d` 那一组整体移到第二行/删掉（简报第 2 条已经在做减法了）。
2. 模型名在数据层截短：`GLM-5.3-Flash` → `GLM-5.3-Flash` 只有 13 字符，
   真正的问题是它挤在两个数字之间。把模型名移到**带子下方**的空行（B 页每张卡片
   `justify-content:center`，带子上下各有余量），它就不再和数字抢宽度，也不会再被截。

### B-4 · **P2** · A 页与 B 页对同一个倒计时报出不同的值 · 置信度 **低（需复现）**

同一批 live 截图、同为 23:00：A 页 ZCode 报 `4h00m`，B 页同一 agent 报 `3h59m`。
可能只是两张图相隔数十秒的拍摄间隔，也可能是 `countdown()` 在 A/B 两处的取整方向不一致（ceil vs floor）。
**修法**：先复现——同一帧同时渲染两页并断言两处字符串相等；若确为取整差异，统一到 floor
（倒计时向下取整才不会出现「0m 后重置」却还没重置的那类谎报，`app.ts:893` 的注释已经踩过一次）。

## 3. C1 / C2 页 · session 列表

### C-1 · **P1** · C1 与 C2 视觉上不可区分，而它们是轮播里相邻的两页 · 置信度 **确定**

**证据**：`m4/live/page-c1.png` 与 `page-c2.png` 并排看——
相同的 64px 徽记列、相同的标题列、相同的右对齐时间列、相同的行高、相同的 ✓ 图标。
两页唯一的差别是**底部第 3 个还是第 4 个点是亮的**（4px 圆点，≈0.64 mm）。
`<h2 class="sr">更早的 session</h2>` 是离屏的，屏上没有任何字说明这是「更早的」。

**机制**：页面身份完全交给了 **4px 的指示点**——一个被简报明写为「不算 accent」的**低优先级、亚阈值**标记。
同时，六页里 **D、E 有可见页标题，A、B、C1、C2 没有**：页眉这一层的**重复（repetition）不成立**，
系统在 2/6 的页上有一套 chrome，4/6 的页上没有。这不是刻意变化（strategic variation），是缺一致性。

**为什么在这块屏上要紧**：轮播每页停 60 s。用户抬头时看到的是**一张静止的画面**，没有翻页动作作线索。
C1 与 C2 在这种条件下是同一张画面的两个版本——读者会以为「屏卡住了」或「刚才看过了」。

**修法（两条选一，不要都做）**：
1. **给所有六页补一个统一的、极轻的页眉**：左上角 14px `--mute` 的一个词
   （`最近 · session` / `更早 · session` / `额度` / `额度详情` / `每日用量` / `今日 AI`），
   与 D/E 已有的标题行合并成同一个槽位。成本是每页顶部 20px——A/B/C 页目前的
   `.pages` 顶部有 `--gap-block` 8px 余量，C 页 feed 还有空行，放得下。
   这一条同时解决「页眉 repetition 不成立」。
2. **或者把 C2 并入 C1 的滚动**，让 8 条 session 变成一页的分时滚动，指示点从 6 个回到 5 个。
   （这条更激进，改动大，且与「一屏只回答一个问题」的轮播前提有冲突，仅列为备选。）

**倾向 1**，因为它顺带把 D/E 的孤立标题纳入系统。

### C-2 · **P2** · C1 → C2 翻页时每一行整体上跳 8–9px · 置信度 **确定**

**机制**：`app.css:245-252`——`.row{height:44px}`、`.row.lead{height:52px}`、
`.page-c .feed{gap:4px}` 且**顶对齐**（`flex-direction:column`，无 `justify-content`）。
C1 有 lead 行 → 块高 52+44×3+4×3 = **196px**；C2 无 lead → 44×4+4×3 = **188px**。差 8px。

**实测**（`m4/live/page-{c1,c2}.png`，器件 px ÷ 4 = 画布 px）：
行 1 差 3.75px、行 2 差 8.75px、行 3 差 8.25px、行 4 差 8.0px。

**为什么算缺陷**：两页的行结构完全一样，读者的眼睛已经在第一页锁定了四条基线；
翻页时**内容该变，版面不该动**。8px ≈ 1.3 mm 的整体位移在静止观看中读成「抖了一下」。
这是 hierarchy-rhythm-review 里「alignment：元素偏离栅格几个像素——是不一致的边距而不是有意的偏移」那一条。

**修法**：把 feed 从「顶对齐的自然流」改成**共享的基线栅格**：

```css
.page-c .feed{ display:grid; grid-template-rows:52px repeat(3,44px); gap:var(--sp-xs); }
```

两页用同一套轨道，C2 的第一行落在 52px 轨道里（16px 文字在 52px 行内略松，可接受，
也可以给 C2 第一行一点额外的 `padding-block` 让它光学居中）。
翻页后四条基线严丝合缝。

### C-3 · **P2** · 同一列里混用相对时间与绝对时钟，两套数字系统 · 置信度 高

`m4/live/page-c1.png` 时间列自上而下：`34 分钟前` / `20:31` / `20:23` / `20:20`。
第一条是 mono 数字 + sans 汉字的混排，其余三条是纯 mono 时钟。
（右边缘对齐是对的，已核 —— 问题不在对齐，在**数字系统**。）
C2 更明显：`20:15` / `16:03` / `14:32` / `9/10 14:41` —— 三种格式。

这是 `whenFmt` 的设计意图（近的用相对、远的用绝对），意图正当；
代价是这一列失去了 **tabular figures 带来的列扫描能力**——读者无法竖着比大小。
**修法（可选，属打磨）**：要么全列统一成绝对时钟（相对时间只留给 running 行，它本来就需要逐秒走），
要么给相对时间也套上定宽（`34 分钟前` → `34m 前`，纯 mono，与 `20:31` 同宽同面）。
**建议后者**——它同时把最长串从 84px 压到 ~50px，给标题让出宽度。

### C-4 · **P2** · 行在静止态没有任何可点的信号 · 置信度 高（但部署场景削弱其影响）

`app.css:245-247` `.row{background:transparent; border:1px solid transparent}` ——
`<button>` 在 rest 态与纯文本行**完全同形**，交互性只在 `:hover` 才浮现（`app.css:280`）。
interaction-states-pass Phase 2.1 明确点名这一条：「只在 hover 才显露交互性的元素——
触摸与键盘用户永远不会 hover」。

**但**：这块屏没有指针也没有常驻键盘，「点击行 = ack」在真机上几乎不发生。
所以这是一个**设计意图问题而不是用户失败**：
如果 ack 在真机上确实不用，那 `.row` 就不该是 `<button>`（它现在进 Tab 序列、占无障碍树里的按钮角色）；
如果 ack 要用，那它需要一个静止态的 affordance。**两者都行，中间态不行。**
交作者拍板，并把结论写进笔记——现在的状态是「两边都留了一点」。

### C-5 · 内容层观察（非设计缺陷，但影响这一页能不能成立）

session 标题里出现 `Reply with only…`、`reply ok`、`延迟测量`——
前两条是原始 prompt 片段而不是会话主题。C 页回答的问题是「谁刚做完」，
而屏上第一行（20px、`--ink`、加粗、全屏最强的那条）写的是 `Reply with only…`。
**版面把最强的强调给了一条没有信息的字符串。** 这不是渲染层能修的，
但它是 C 页价值的上限，建议回给数据侧（session 标题的抽取规则）。

## 4. D 页 · 每日用量热力图

**这一页是本次评审问题最集中的一页。** 它回答的问题是「我用得多不多、哪几天最猛」，
而当前版面把答案缩成了屏幕中央的一枚邮票。

### D-1 · **P1** · 格子尺寸写死 13px，热力图只占可用宽度的 30%，整页约 89% 是空的 · 置信度 **确定**

**页面 / 选择器**：`src/renderer/app.ts:554` `const cell = 13`
＋ `app.css:316` `.d-cells{grid-template-rows:repeat(7,var(--cell)); flex:none}`
＋ `app.css:311` `.d-grid{justify-content:center}`

**证据 + 量化**（`m4/live/page-d.png`）：

```
.dwrap 可用宽 = 387px（画布 403 − screen inset 16）
d-grid 可用宽 = 387 − d-days 26 − gap 8 = 353px
实际格子区宽 = 8 列 × (13+2) − 2 = 118px      →  占 353 的 33%，占 387 的 30%
实际格子区高 = 7 行 × (13+2) − 2 = 103px      →  占 d-grid 高 142 的 73%
单格物理尺寸 = 13 px × 0.16 mm = 2.08 mm（55 cm 处约 0.22° 视角）
```

器件坐标复核：格子区 x ∈ [760, 1320]、y ∈ [310, 735]（1920×1080 图），与上式一致。

**机制**：`cell` 是常量，`cols` 是**从宽度反推出来的上限**（`app.ts:556-557` 算出 23），
但实际列数由数据决定（8 周 = 8 列）。于是宽度预算算了、却没有回流到格子尺寸上——
**版面按 26 列设计，数据给了 8 列，中间没有自适应这一步**。
居中（`justify-content:center`）是为了避免右侧空白读成「没加载出来」（注释写明了），
这个判断是对的，但它治的是症状：真正的问题是格子没有长大。

**为什么是 P1**：这是唯一一页需要**分辨密度差异**的页，而当前的单格只有 2.08 mm。
在 0.16 mm/px、55 cm 的条件下，2 mm 的方块之间要分辨 5 档明度阶（见 D-2），
物理上办不到。这一页当前**回答不了它自己提出的问题**。

**修法**：把 `cell` 从常量改成**由较小的那个预算推出**，并保留一个上限：

```ts
const gridW = avail - 26 - 8                     // 353
const gridH = el.pdHeat.clientHeight - 20 - 8 - 20 - 8   // ≈142
const cols  = Math.ceil(days.length / 7)
const cell  = Math.max(10, Math.min(28,
  Math.floor((gridW + 2) / cols) - 2,
  Math.floor((gridH + 2) / 7)    - 2))
```

代入今天的数据：宽度给 `floor(355/8)-2 = 42`，高度给 `floor(144/7)-2 = 18` → **cell = 18px**。
格子区变成 158 × 138，**填满 100% 的高度**（今天 73%），单格 2.88 mm（+38% 线性尺寸，+92% 面积）。
数据长到 26 周时同一公式给出 `floor(355/26)-2 = 11`，自动降回密排——**它自己会退化，不需要再改**。

**一个需要作者拍板的取舍**：18px 方格仍只填 45% 的宽度。要填满宽度必须放弃正方形
（42 × 18 的非方格，长宽比 2.3:1）。GitHub 式热力图默认方格，但这块屏是 3:2 且只有 8 列——
**非方格是一个合法的、故意的选择，只要写进笔记**。方格 + 左对齐到标题的光学边、
把右侧空间给 D-3 的说明行，也是一个解。**不替作者选，但必须选一个**：现状（小方格居中、两边大片空）
是三个选项里最差的那个。

### D-2 · **P1** · 五档明度阶在 2 mm 格上不可分；0 档对底色 1.05:1，等于看不见 · 置信度 **确定**

**实算**（`tokens.css:266-270`，WCAG 相对亮度公式）：

| 相邻档 | 色值 | 对比度 |
|---|---|---|
| canvas → heat-0 | `#07080a` → `#101111` | **1.05 : 1** |
| heat-0 → heat-1 | `#101111` → `#2b2c2e` | 1.36 : 1 |
| heat-1 → heat-2 | `#2b2c2e` → `#4d4f52` | 1.70 : 1 |
| heat-2 → heat-3 | `#4d4f52` → `#8a8c91` | 2.45 : 1 |
| heat-3 → heat-4 | `#8a8c91` → `#d3d3d4` | 2.24 : 1 |
| heat-0 → heat-4（全程） | | 15.0 : 1 |

设计笔记「未验证 §3」已经预判了这一条，并把它挂起等实机确认。**现在确认：分不开。**
`m4/live/page-d.png` 左侧三列（全 0 档）与 canvas 之间**在图上几乎读不出格子的存在**——
而这块屏比截图暗、比截图小。

**两个层次的后果**：
1. **0 档 1.05:1 意味着「热力图有多宽」这件事本身不可见。** 用户看到的是右侧五列亮格子，
   看不到左侧那三列「这几周没用」——而「没用」恰恰是「用得多不多」这个问题的另一半答案。
   且 `.cell` 是 `<button>`、在 `←→` 焦点链上，一个不可见的可聚焦组件在 WCAG 1.4.11 上是有争议的
   （**此条存疑，不作为硬失败计**，因为「零用量」渲染成近乎不可见也可以辩护为语义正确）。
2. **1–4 档之间 1.36 / 1.70 是 GitHub 也做不到的**，单靠颜色确实不可能——
   但 GitHub 有 hover tooltip 兜底，**这块屏没有指针**。所以这里的兜底只剩 D-3 那一行，而它被截断了（见下）。

**修法（按代价排）**：
1. **先做 D-1**：格子从 2.08 mm 长到 2.88 mm，同样的对比度在更大的色块上更容易分辨
   （对比敏感度随空间频率下降而上升）。这是最便宜的一步，**先做它再评估是否还需要动色阶**。
2. **把 0 档提到可见**：`--heat-0` 从 `--surface-elevated #101111` 提到 `--stone #434345`
   （对 canvas 3.2:1，格子的存在可见），1–4 档整体向上平移，顶档仍 `--charcoal`。
   代价是 0 档不再「消失」——但这正是要的：**格子该显示的是「这一天有记录且用量为零」，不是「这一天不存在」**。
   （真正不存在的那几格已经有 `data-void="1"` → `transparent`，语义是分开的，只是视觉上今天分不出来。）
3. **不要**为了对比度去换色相（比如加回蓝/绿）——设计笔记里「不用 accent-blue 免得与 ZCode 身份色混淆」
   的推理是对的，那条约束应当保留。用中性阶的明度范围，不用色相。

### D-3 · **P1** · 唯一承载精确值的说明行，把第三家 agent 整个截掉了 · 置信度 **确定**

**页面 / 选择器**：`app.css:325-329` `.d-tip` / `.d-tip .dim` / `.d-scale`
＋ `app.ts:595-597` 的 `parts.join(' · ')` ＋ 5 个色阶方块

**证据**：`m4/live/page-d.png` 底行 ——
`2026-09-14  Codex 0 tok · Claude 6.0亿 tok · …`
**ZCode 那一段完全没有出现。** 三家里少一家。

**宽度账**：

```
行宽 387
  <b> 日期 "2026-09-14" 14px mono ×10 ×8.4 = 84
  gap --sp-sm                              =  8
  .d-scale 5×8px + 4×4px gap + margin 8    = 64
  → .dim 实得                               = 231px
  实际内容 "Codex 0 tok · Claude 6.0亿 tok · ZCode 233 次" ≈ 308px
  → 溢出 77px，省略号落在第三家的开头
```

**机制**：与 E-1、B-3 **同一个模式**——可变长的集合与定长的装饰共处一个裁切盒，
被牺牲的永远是集合的尾巴。设计笔记为 E 页的时间修过一次这个错（把时间 `flex:none`），
但**没有把结论推广成规则**，于是它在 D 页原样重现。

**加重情节**：`.d-tip` 是这块屏上**唯一**的精确值出口。设计笔记明写
「颜色只负责分布，数字负责精确」——可这块面板没有指针，hover 永远不会发生，
`.d-tip` 显示的是 `showTip(last)` 兜底的最后一格。**它就是 tooltip 本身，而它缺了三分之一。**

**修法（任选其一即可回收 77px，建议前两条一起做）**：
1. **删掉 `.d-scale` 那 5 个方块**（回收 64px）。它没有「少 / 多」锚点标签，
   5 个 8px（1.3 mm）的灰方块在 55 cm 外只是一串噪点，**解释不了任何东西**——
   而它占的正是被截掉的那段。要么给它配上 `少 ▢▢▢▢▢ 多`（再吃 56px，更挤），要么删掉。**删掉。**
2. **日期挪走**（回收 92px）：`2026-09-14` 可以合并进页标题（`每日用量 · 近 8 周` → 
   `每日用量 · 2026-09-14`），或者缩成 `09-14`（回收 50px）。
3. **改成两行**：页面在格子区下方有约 90px 的纵向余量（见 D-1 的高度账），
   完全放得下第二行。`flex-direction:column` 即可。
4. 无论选哪条，**给 `.dim` 的截断补一个明确的语义**：三家里任何一家缺失都应当
   显式渲染为 `ZCode —`，而不是被省略号吞掉。补一条内容级断言：
   `.d-tip` 的文本必须同时含 `Codex` / `Claude` / `ZCode` 三个字面量。

### D-4 · **P1** · 身份色图例挂在一张单色网格上，主动误导 · 置信度 **确定**

**页面 / 选择器**：`app.ts:572-573` ＋ `app.css:305-308` `.d-legend`

**证据**：`m4/live/page-d.png` 右上角 —— `● Codex  ● Claude  ● ZCode`，三个身份色圆点。
正下方是一张**完全按总量分档的中性灰网格**。

**机制**：图例（legend）在数据可视化里的契约是「这些颜色在这张图上代表这些类别」。
这里三个彩色点下面没有任何彩色编码——**图例承诺了一个不存在的 encoding**。
设计笔记 §「三个要解释的决定」里，设计师**自己写下了这个担心**
（「一屏蓝格子加一个蓝图例点会让人以为格子按 agent 分了色」），
然后为此放弃了蓝色阶——却把会造成同样误读的图例本身留下了。

**为什么是 P1 而不是打磨**：ai-slop-check 的核心判据是「这个元素是为读者存在的，
还是因为这类页面通常有它」。**一个不解释任何东西的图例，比没有图例更糟**——
它不是装饰，它是错误信息。

**修法（按信息价值排）**：
1. **首选：把三个点换成当日/当周各家的实际占比**，让图例变成数据
   （`● Codex 0 · ● Claude 6.0亿 · ● ZCode 233`）——这正好接管 D-3 里被截掉的那一行，
   两条一起修：说明行只留日期 + 分档信息，agent 分量上移到页眉，各得其所。
2. 次选：**整块删掉**。页标题 `每日用量 · 近 8 周` 已经说清了这一页是什么。
3. **不要**改成按 agent 分色的格子——简报明确要求「格子只按总量分档」。

### D-5 · **P2** · 星期标签只给一、三、五、日 · 置信度 高

`app.ts` 的 `DAY_LABEL` 交替留空（GitHub 惯例）。GitHub 这么做是因为它的格子只有 10px 且有 53 列，
标签放不下。这里只有 7 行、左侧 26px 列、且整页 89% 是空的——**省略的理由不成立**，
读成「标签没渲染全」。做完 D-1（行高 18px）之后七个字全放得下。补齐。

### D-6 · **P2** · `.cell` 的无障碍名报的是档位不是数值；`cursor:default` 与可聚焦矛盾；焦点入口只有最后一格

- `app.ts:567` `aria-label="${d.date} 用量第 ${lv} 档"` —— 屏幕阅读器听到「第 3 档」而没有任何标度参照。
  应当报**数值**：`2026-09-14 · Codex 0 · Claude 6.0亿 · ZCode 233`，与 `.d-tip` 同源。
- `app.css:317` `.cell{cursor:default}` 加在一个 `<button>` 上 —— 指针语义说「不可交互」，
  DOM 与键盘行为说「可交互」。二选一。
- `app.ts:566` 所有格子初始 `tabindex="-1"`，`app.ts:610-611` 只把**最后一格**提到 0。
  roving tabindex 的实现是对的，但入口是「最后一格」而不是「今天 / 第一格」——
  Tab 进来落在右下角，`←` 才是数据方向。建议入口设为**今天**（最后一格恰好是今天，
  那就在注释里说明这是刻意的，现在读起来像是「取了个末元素」）。

### D-7 · **P2** · `cell = 13px` 离间距栅格 · 置信度 确定

画布里仅有的三个离格值之一（另两个：`.b-head{height:22px}`、`.d-days{width:26px}`）。
做完 D-1 后 `cell` 变成推导值，这条自动消失；`22` / `26` 建议归到 24 / 28。
**整体评价：这套 CSS 的栅格纪律是好的**，这三个是仅剩的例外，值得清掉以便断言可以收紧成硬线。

## 5. E 页 · 今日 AI 大事

### E-1 · **P1** · 来源列被截到不含信息（「公众号：…」），E 页的旧修复只是把裁切从时间挪到了来源 · 置信度 **确定**

**页面 / 选择器**：`app.css:353-356` `.e-meta` / `.e-src` / `.e-time`
＋ `app.css:346` `.e-item{grid-template-columns:18px minmax(0,1fr) minmax(0,34%)}`

**证据**：`m4/live/page-e.png` 三条的来源列 ——
`公众号： …` / `Gary M…` / `Hacker New…`。
第一条**只剩下「公众号：」四个字加省略号**，真正的来源名一个字都没有。

**机制**：`.e-meta` 第三列硬性 `minmax(0, 34%)` ≈ 132px，
`.e-time`（`flex:none`）先取走 `5 小时前` ≈ 56px + gap 4，`.e-src` 实得约 72px。
14px 下 72px 只够 5 个全角字。上一轮补丁把 `.e-time` 设成 `flex:none` 是对的
（保住了必须出现的字段），但**没人检查剩下那一半还够不够读**——
`公众号：` 这个前缀恰好把 72px 用完，信息量为零。

这是与 D-3、B-3 **完全同一个模式**的第三次出现。

**修法（数据层 + 版面层各一半）**：
1. **数据层先剥前缀**：`公众号：小红书技术（dots.llm）` → `小红书技术`；
   `Gary Marcus：The Road to AI We Can Trust（RSS）` → `Gary Marcus`；
   `Hacker News：AI 热帖` → `Hacker News`。
   规则：取全角/半角冒号前后较短且更具识别度的那一段，去掉括注。
   真实来源名剥完普遍 ≤ 6 个全角字，72px 正好够。
2. **版面层加一条内容级断言**（与 `.e-time` 那条配对）：
   `.e-src` 的 `scrollWidth` 不得超过 `clientWidth` 的 1.6 倍——
   即「允许省略，不允许省略到只剩前缀」。这条断言可推广到 D-3 与 B-3。
3. 若 1 做不到，**退而砍掉来源列**，只留时间。简报要求「来源与相对时间」，
   但一个读不出来的来源不构成署名——底部已经有 `数据来源：AIHOT` 承担了署名义务。

### E-2 · **P2** · 3 条内容下的下三分之一是空的，署名行悬在半空 · 置信度 确定

`m4/live/page-e.png`：第 3 条结束于 y≈800/1080，`数据来源：AIHOT` 紧跟在 y≈855，
指示点在 y≈1015 —— 中间有一块 160 器件 px（40 画布 px）的空白，
版面读成「下面还有第 4、5 条但没加载出来」。

设计笔记「未验证 §1」已挂起这一条（AIHOT 今天只给 3 条），
并且**正确地拒绝了编两条假新闻去填满**——这个判断要保留。
但「不编内容」不等于「不处理空缺」。

**修法**：`.e-list` 用 `flex:1` 让三条**均分整个可用高度**（现在每条 `flex:1` 但列表本身没撑满？
实测三条挤在上 2/3），并把 `.e-foot` 用 `margin-block-start:auto` 钉到列表底部。
条数少时三条自然拉开、行距变松——**这读成「今天就这三条」，而不是「没加载完」**。
条数满 5 时回到紧排，`--e-lines` 的逻辑（`app.ts:658`）已经在做这件事。

### E-3 · **P2** · 一列里三种时间格式，且「今日 AI」里出现了 9/13 的条目 · 置信度 高

`m4/live/page-e.png` 时间列：`5 小时前` / `20 小时前` / `9/13`。
`newsWhen`（`timefmt.ts`）在 24 h 处切换相对/绝对，逻辑正当，
但结果是同一列三种排版形态，且第三条**标题写着「今日 AI」、时间写着昨天**。
**修法**：E 页把上限放宽到 48 h 并统一用相对式（`36 小时前`，最长 6 字符 ≈ 60px，
比 `9/13` 只多几 px），或者页标题改成 `AI 速览 · AIHOT` 去掉「今日」的承诺。
**倾向后者**——改一个词，比改时间格式便宜，而且诚实。

### E-4 · **P2** · 右上角两个都是时间、都没有标签、上下叠着 · 置信度 高

`23:00`（`.clock`，14px mono `--mute`）正下方是 `刚刚`（`.e-upd`，14px `--mute`）。
两个同色同号的时间值垂直相邻，读者要自己推断上面是墙钟、下面是数据更新时刻。
**修法**：给 `.e-upd` 一个两字前缀（`更新 刚刚`，+28px，那一行有余量），
或把它移到 `数据来源：AIHOT` 那一行（`数据来源：AIHOT · 刚刚更新`），
让顶栏在六页上保持「只有时钟」这一个不变量。**后者更好**——它保住了顶栏的一致性。

## 6. attention 页

> **以下全部基于 `design/shots/page-attention-x119.png`（原型图，非 M4 真机）。
> 未在 M4 构建上验证，结论需要作者用真机图复核一次。**

### ATT-1 · **P2** · accent 圆点是为了通过断言而存在的元素，位置在最不被看的那个角

`app.css:372` `.attn-dot{top:var(--sp-md); right:var(--sp-md)}` —— 6px `--accent` 白点，卡片右上角。
设计笔记 R5-20 写明了它的来历：「原来却是全屏 0 处 accent……做成真实元素而不是伪元素——
伪元素躲得过 accent 全量扫描」。

**这句话本身就是诊断**：它是为了让扫描器数到 1 而加的。
读者视线在 LTR 里从左上起步，这一页的信息主轴是
`● CLAUDE`（左上）→ `↵ 等待你`（28px，最强）→ 说明句 → meta，
右上角 6px 的白点在这条路径之外，**没有一个读者会因为它而理解得更快**。
而这一整屏本身就是「需要你」——accent 的定义在这里被整页承担了，不需要再点一次。

**修法**：删掉 `.attn-dot`，同时把 accent 断言从「计数 ≥1」改成
「attention 态下 `.page-attn` 必须可见且 `--fs-attn-lead` 文本非空」——
**断言应当检查读者能不能理解，而不是检查有没有某个色块**。
若要保留一个 accent，把它并进 `.attn-who` 左侧那个身份点（让它在 attention 态转 `--accent`），
它在视线的起点上，而且已经有位置。

### ATT-2 · **P2** · attention 接管时，指示点一个都不亮

原型图底部 5 个点全为 `--ash`，没有一个是 `--ink`。
attention 页不在轮播序列里（简报：它不能被手动切走），所以 `renderDots` 找不到匹配项。
结果是「当前状态不可见」（interaction-states-pass Phase 4 末段）——
指示点在说「你不在任何一页上」。
**修法**：attention 接管时**整排隐藏**指示点（它本来也点不动），
或把整排替换成一条 14px 的 `--mute` 文字（`已暂停轮播`）。前者更干净。

### ATT-3 · **P2** · `.attn-what` 从右侧截断路径，切掉的正是文件名

`app.css:377` `.attn-what{white-space:nowrap; text-overflow:ellipsis}`，
当前内容 `批准写入 ~/.claude/settings.json` 恰好放得下。
但路径一长，从右截断切掉的是 **文件名**——路径里信息密度最高的那一半
（与 E 页时间那个 bug 是同一条教训：**被裁掉的一定是排在后面那个，而它往往才是要紧的**）。
**修法**：路径类文本改成保尾截断
（`direction:rtl; text-align:left; unicode-bidi:plaintext`，或在数据层做中段省略
`~/.claude/…/settings.json`）。

### ATT-4 · **P2** · 路径用比例字排

`~/.claude/settings.json` 渲染在 18px Inter 里，与前面的「批准写入」同面。
项目自己立的规矩是「数字用 Plex Mono，名字用 Inter」——路径两者都不是，
但它属于**等宽类内容**（斜杠、点、下划线在比例字里间距不均）。
建议路径段套 `.mono`。低优先级。

## 7. 跨页与实现层

### X-1 · **P1** · 「裁切但不省略」是一个类（见 A-1b），且 `verify.mjs` 在结构上看不见它

已在 A-1b 详述。单列在这里是因为它跨 A / B / C 三页，修法应当一次做完，
并配一条内容级断言，否则第六次同型问题会在下一个页面复现。

### X-2 · **P2** · connect 窗口的输入框把一整句说明当成了可访问名

`src/renderer/connect.html`：

```html
<p class="lede" id="lede">粘贴智谱 bigmodel 的 API Key，保存进 macOS 钥匙串，不落盘明文。</p>
<input id="key" type="password" autocomplete="off" aria-labelledby="lede" placeholder="API Key">
```

屏幕阅读器会把整句 28 字的说明念成这个字段的**名字**。
可访问名应当短而稳定（`API Key`），说明句是**描述**。
**修法**：

```html
<label for="key" class="sr">API Key</label>
<input id="key" type="password" aria-describedby="lede" …>
```

（`placeholder` 保留作视觉提示即可；accessibility-audit 明写「placeholder 单独不构成 label」。）
其余部分是好的：`role="status" aria-live="polite"` 的 `.msg` 在位，
focus 环 2px `--ink` + offset 1px，按钮 hover / focus-visible 齐备，CSP 极严。

### X-3 · 未能验证（交作者补）

1. **attention 页没有 M4 真机图**（ATT-* 全部基于原型图）。
2. **七态里只看到了 populated。** `loading` / `empty` / `error` / `edge` / `running` 的真机表现未评。
   D 页的 edge（离群值把其余压进第 1 档）与 A/B 的 `danger` 配色（数字转红 + 警示图标承担阈值）
   是这一轮改动最大的两处，**建议补这两张真机图再定稿**。
3. **未读 / accent 机制在交付图上一次都没出现**：六页 live 图里 `data-unread="1"` 一个都没有，
   `.rmark` 全是透明。accent ≤2 这条纪律因此是「因为一处都没有而通过」，不是「因为控制得当而通过」。
   建议补一张有未读行的真机图。
4. **D 页 26 周时的密度**（今天只有 8 周）。做完 D-1 后公式会自动降档，但没实测过。

### 结论：**修完 8 条可交付**

不是「可交付」，也不是「需再迭代」。

**理由**：这一版的**系统层是健康的**——reduced-motion 完整、focus 纪律严格、
语义结构与 `inert` 正确、时长全部在 band 内、ai-slop 六项全清、间距栅格只有 3 个例外。
这些是最贵、最难回头补的部分，都做对了。
剩下的问题**全部是「最后一公里」的宽度预算与层级取舍**，
集中在两个可命名的模式上，改动面小、风险低：

1. **裁切策略只写了一半**（A-1 / A-1b / A-2 / B-3 / D-3 / E-1 —— 六处，同一个病）：
   把「必须完整出现的字段」和「可变长的字段」塞进同一个定宽裁切盒，
   被牺牲的永远是排在后面那个，而断言只看溢不溢出、看不见信息还在不在。
2. **非信息性元素占了信息性元素的视觉位**（B-1 轨道 / D-4 图例 / D-1 空白 / ATT-1 accent 点）：
   `--ash` 轨道、无 encoding 的图例、为断言而生的圆点——
   它们都在版面上占着最好的位置，而读者从它们身上得不到任何东西。

这两条都不是「再迭代」级别的问题（结构没错、方向没错），
但也都不能在交付时留着——第 1 条会让用户读到残缺字形，第 2 条会让用户读错数据。
